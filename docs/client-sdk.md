# SDK network cho Unity (`yarn unity:network`)

Server sinh sẵn toàn bộ code gọi API / room cho Unity vào `../ERPG/Assets/Src/Scripts/Network`. Thêm hoặc sửa
API / room → chạy lại lệnh là client dùng được ngay. RPC giữa các room là nội bộ server nên **không** export.

```bash
yarn unity:network          # ghi vào Unity (chỉ ghi file đổi, xoá file cũ không còn)
yarn unity:network:check             # chỉ so sánh, exit 1 nếu lệch (dùng cho CI)
yarn unity:network --admin  # thêm endpoint /admin (mặc định chỉ /user)
```

`yarn unity:network` chạy hai bước: (1) Colyseus schema-codegen sinh state + DTO `...Message` + catalog code rồi xếp vào
`Room/<Room>/Schema` (theo room chứa kiểu đó) hoặc `Common` (`scripts/generate-room-schemas.mjs`); (2) sinh SDK.
`unity:network:check` chỉ so sánh phần SDK.

## Cấu trúc thư mục Unity

```
Network/
├── ERPG.Network.asmdef      # SINH từ scripts/sdk/runtime
├── Runtime/                 # SINH từ scripts/sdk/runtime: Result / Result<T>, ApiClient, RoomClient<T>, NetworkSettings, NetworkSession, KickCode, ClientErrorCode
├── README.md                # SINH từ scripts/sdk/runtime: hướng dẫn dùng cho client (Unity)
├── Common/                  # SINH: kiểu dùng chung — catalog code (MapCode, ItemCode...), enum chung (ERPG.Schema)
├── Errors/                  # SINH: một static class mỗi enum mã lỗi (hằng số + XML doc)
├── Api/<Role>/<Module>/     # SINH: <Role><Module>Api.cs (hàm gọi) + Models/ (request / response)
└── Room/<Room>/             # SINH: <Room>RoomClient.cs (gửi / nhận message) + Payloads/ + Schema/ (state, DTO ...Message của room, namespace ERPG.Schema)
```

Chỉ có một assembly `ERPG.Network` (đã bỏ `ERPG.Schema.asmdef`; namespace schema vẫn là `ERPG.Schema`). Mọi thư mục SINH có header `<auto-generated>` và được ghi trong `.sdk-manifest.json`; không sửa tay. Runtime, asmdef và README cũng do export ghi (nguồn: `scripts/sdk/runtime/`) — sửa ở server, không sửa bên Unity.

## Nguồn dữ liệu trên server

| Cái cần sinh                              | Khai báo ở đâu                                                                                       |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Hàm API                                   | option `sdk` của endpoint trong `src/apis/<role>/<module>/controllers`                               |
| Kiểu request                              | Zod `body` / `query` / `params` của endpoint (schema export trong `validators/*.validator.ts`)       |
| Kiểu response                             | `sdk.response` — Zod schema export trong `validators/*.response.ts`                                  |
| Message client → server của room          | command có `static readonly message = Enum.X` (tự suy)                                               |
| Payload của message                       | Zod schema mà command `safeParse`/`parse`/`client.parsePayload(schema, …)`/gán vào `validateSchema` (tự suy) |
| Kiểu `data` của message server            | kiểu đối số `data` tại các chỗ gọi `sendSuccess`/`sendResult`/`broadcast*` (tự suy)                  |
| Tài liệu message (reply, mã lỗi, ghi chú) | decorator `@SdkMessage` trên command                                                                 |
| Cách join room                            | decorator `@SdkRoom` trên class room                                                                 |
| Mã lỗi + giải thích                       | JSDoc từng member của enum mã lỗi (`*-error-code.enum.ts`, `*-error-code.type.ts`)                   |
| Mô tả message room                        | JSDoc từng member của enum message (`world-message.type.ts`...)                                      |

### Thêm endpoint

```ts
userPlayerRename: playerEndpoint(
    `${prefix}/me/name`,
    {
        method: "PUT",
        body: UserRenamePlayerSchema,
        sdk: {
            summary: "Đổi tên nhân vật đang chọn.",
            auth: "player", // "none" | "user" | "player" — token nào được gắn
            response: UserPlayerMeResponse, // Zod schema, hoặc null (không có data), hoặc "raw"
            errors: [PlayerErrorCode.PLAYER_NAME_INVALID, PlayerErrorCode.PLAYER_NAME_EXISTS],
        },
    },
    handler
);
```

- Endpoint thiếu `sdk` thì export **thất bại** và liệt kê endpoint thiếu; không muốn export thì `hidden: true`.
- Schema export trong `validators/*.validator.ts|*.response.ts` được đặt tên class C# theo tên export
  (`UserCreatePlayerSchema` → `UserCreatePlayerRequest`, `UserAuthResultResponse` giữ nguyên) và dùng chung giữa
  các endpoint. Object viết inline được đặt tên theo class cha + tên field.
- `errors` chỉ ghi mã nghiệp vụ của endpoint; `INVALID_INPUT`, `MISSING_TOKEN`, `INVALID_TOKEN`,
  `INTERNAL_ERROR`, `NETWORK_ERROR` được thêm tự động vào XML doc theo `auth` và input.
- `response: "raw"` chỉ là tạm (client nhận `object`, export in cảnh báo).
- Response schema chỉ gồm field client dùng; server trả thêm field khác thì client bỏ qua. Đổi shape trả về của
  service thì sửa schema tương ứng.

### Thêm / sửa message room

1. Thêm member vào enum (`WorldClientMessage` / `WorldMessage` / `Party*Message`) kèm JSDoc — JSDoc thành
   `<summary>` của hàm C#.
2. Viết command với `static readonly message = Enum.X` và Zod schema của payload. Hàm gửi, class payload và hàm
   `On...` có kiểu được **tự suy**, không cần khai báo thêm.
3. Muốn doc có reply / mã lỗi / ghi chú thì gắn decorator lên command:

    ```ts
    @SdkMessage({
        replies: [WorldMessage.INVENTORY, WorldMessage.ATTRIBUTES], // message server trả lời
        errors: [ItemErrorCode.ITEM_CLASS_MISMATCH, PlayerErrorCode.LEVEL_TOO_LOW], // mã lỗi nghiệp vụ
        note: "Payload sai thì server im lặng.", // trường hợp đặc biệt
    })
    export class EquipItemWorldCommand extends InventoryWorldCommand<...> {
    ```

    Command con gộp metadata của lớp cha: lỗi chung khai báo một lần ở lớp cha (vd `InventoryWorldCommand`).
    Command không có `@SdkMessage` vẫn có hàm gửi và payload, chỉ thiếu phần doc reply / lỗi.

4. DTO mới của `data` khai báo trong `world-message.type.ts` / `party-message.type.ts` (interface `...Message`;
   phải có tên kết thúc bằng `Message` để schema-codegen sinh C#), rồi `yarn unity:network`.
5. Room mới: `@SdkRoom({ joins: [{ room, options: <Zod|null>, doc }] })` trên class room.

Giới hạn của tự suy: `data` phải có kiểu được đặt tên (`satisfies Xxx` / biến có kiểu), object literal trần sẽ ra
`Result` không có data. Payload chỉ suy được khi command dùng trực tiếp một Zod schema đặt tên.

### Mã lỗi

Thêm mã vào enum domain kèm JSDoc: khi nào server trả, client nên làm gì, `error` kèm dữ liệu gì. Chú thích đó
thành XML doc của từng hàm dùng mã đó và của hằng số trong class `*ErrorCode`. SDK không có bảng văn bản hiển thị: client map mã → locale key của game (bảng locale do game tự giữ).

## Dùng ở client

Gọi **thẳng** code sinh ra từ scene / HUD / view — không viết lớp wrap lại hàm mạng. Logic xử lý cụ thể (toast, mở modal, cập nhật state) nằm ở nơi dùng.

```csharp
// Khởi động (một lần): NetworkSession.Initialize(serverUrl) — nối ServerUrl, token (lưu PlayerPrefs), tự xoá phiên khi token hỏng.

// API: không ném exception, luôn là Result<T>. Có overload tham số phẳng cho body/payload đơn giản.
var created = await UserPlayerApi.Create(name: "An", classCode: "swordsman");
if (!created.success)
{
    if (created.Is(PlayerErrorCode.PLAYER_NAME_EXISTS)) { /* chọn tên khác */ }
    return;
}
NetworkSession.SetPlayer(created.data.playerToken);

// Room: client tạo một lần, đăng ký handler trước hay sau khi join đều được (tự gắn lại khi join lại).
var world = new WorldRoomClient();
world.OnInventory(inventory => Render(inventory));                         // chỉ gọi khi thành công
world.OnUpgradePreview(preview => Show(preview), failure => ShowError(failure.code)); // + nhánh lỗi riêng
await world.JoinWorld(new WorldJoinOptions { mapCode = "greenfield_village" });
await world.WaitForFirstState();
await world.EquipItem(instanceId);                                         // overload phẳng; hoặc EquipItem(new EquipItemRequest {...})
```

- **Lỗi tập trung:** `ApiClient.Failed` (API) và `RoomClient.Failed` (mọi message room thất bại) bắn trước khi handler riêng chạy — bootstrap của game
  đăng ký một lần để log + toast theo locale. `ApiClient.Unauthorized` đưa về màn đăng nhập. Close code khi bị đá khỏi room: `KickCode`.
- **`OnX(onOk, onFail = null)`:** `onOk` nhận `data` khi thành công; `onFail` nhận `Result` (có `code`, `error`) khi cần xử lý lỗi riêng. Message không có
  dữ liệu (`OnDungeonRetryResult`...) nhận `Action<Result>` cho cả hai nhánh.
- **Overload phẳng:** sinh thêm khi payload / body chỉ gồm field đơn giản; field bắt buộc đứng trước, tuỳ chọn có mặc định `null`. Tên message trùng
  thành viên của `RoomClient` (`Leave`...) được thêm tiền tố `Send` (`SendLeave`).

Chi tiết từng lớp trong `Runtime/` và cách dùng: `Network/README.md` bên Unity.
