# SDK network cho Unity (`yarn unity:network`)

Server sinh sẵn toàn bộ code gọi API / room cho Unity vào `../ERPG/Assets/Src/Scripts/Network`. Thêm hoặc sửa
API / room → chạy lại lệnh là client dùng được ngay. RPC giữa các room là nội bộ server nên **không** export.

**Yêu cầu Unity:** Colyseus Unity SDK **>= 0.18.3** (Request/Response; 0.18.0 đến 0.18.2 thiếu file `.meta` nên `Room.cs` không build). Room dùng
`await room.Request<T>(type, payload, timeoutMs)`; lỗi giao thức là `RequestError { Name, Code, Payload, Faulted }` hoặc `TimeoutException`
(SDK sinh ra đã bọc thành `Result` thất bại).

Đường dẫn xuất đổi được: `yarn unity:network <thư-mục>` (hoặc env `UNITY_NETWORK_OUTPUT` cho bước schema), vd để thử vào thư mục tạm.

```bash
yarn unity:network          # ghi vào Unity (chỉ ghi file đổi, xoá file cũ không còn)
yarn unity:network:check             # chỉ so sánh, exit 1 nếu lệch (dùng cho CI)
yarn unity:network --admin  # thêm endpoint /admin (mặc định chỉ /user)
```

`yarn unity:network` chạy hai bước: (1) Colyseus schema-codegen sinh state + DTO `...Message` + catalog code rồi xếp vào
`Room/<Room>/Schema` (theo room chứa kiểu đó) hoặc `Common` (`scripts/generate-room-schemas.mjs`); (2) sinh SDK.
`unity:network:check` chỉ so sánh phần SDK.

## Cấu trúc thư mục Unity

```
Network/
├── ERPG.Network.asmdef      # SINH từ scripts/sdk/runtime
├── Runtime/                 # SINH từ scripts/sdk/runtime: Result / Result<T>, ApiClient, RoomClient<T> (Call/Request, push hub), NetworkSettings, NetworkSession, KickCode, ClientErrorCode
├── README.md                # SINH từ scripts/sdk/runtime: hướng dẫn dùng cho client (Unity)
├── Common/                  # SINH: kiểu dùng chung — catalog code (MapCode, ItemCode...), enum chung (ERPG.Schema)
├── Errors/                  # SINH: một static class mỗi enum mã lỗi (hằng số + XML doc)
├── Api/<Role>/<Module>/     # SINH: <Role><Module>Api.cs (hàm gọi) + Models/ (request / response)
└── Room/<Room>/             # SINH: <Room>RoomClient.cs (request async + nhận push) + Payloads/ + Schema/ (state, DTO ...Message của room, namespace ERPG.Schema)
```

Chỉ có một assembly `ERPG.Network` (đã bỏ `ERPG.Schema.asmdef`; namespace schema vẫn là `ERPG.Schema`). Mọi thư mục SINH có header `<auto-generated>` và được ghi trong `.sdk-manifest.json`; không sửa tay. Runtime, asmdef và README cũng do export ghi (nguồn: `scripts/sdk/runtime/`) — sửa ở server, không sửa bên Unity.

## Nguồn dữ liệu trên server

| Cái cần sinh                                              | Khai báo ở đâu                                                                                               |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Hàm API                                                   | option `sdk` của endpoint trong `src/apis/<role>/<module>/controllers`                                       |
| Kiểu request                                              | Zod `body` / `query` / `params` của endpoint (schema export trong `validators/*.validator.ts`)               |
| Kiểu response                                             | `sdk.response` — Zod schema export trong `validators/*.response.ts`                                          |
| Message client → server của room (request)                | command có `static readonly message = <Room>ClientMessage.X` (tự suy)                                        |
| Payload của message                                       | Zod schema mà command `safeParse`/`parse`/`client.parsePayload(schema, …)`/gán vào `validateSchema` (tự suy) |
| Kiểu `data` của **response**                              | `@SdkMessage({ response: "XxxMessage" })` hoặc `"string"` trên command (bỏ trống = không có data)            |
| Kiểu `data` của **push** (server → client)                | kiểu đối số `data` tại các chỗ gọi `sendSuccess`/`sendResult`/`sendTo`/`broadcast*` (tự suy)                 |
| Tài liệu message (response, push đi kèm, mã lỗi, ghi chú) | decorator `@SdkMessage` trên command                                                                         |
| Cách join room                                            | decorator `@SdkRoom` trên class room                                                                         |
| Mã lỗi + giải thích                                       | JSDoc từng member của enum mã lỗi (`*-error-code.enum.ts`)                                                   |
| Mô tả message room                                        | JSDoc từng member của enum message (`world-message.type.ts`, `global-message.type.ts`)                       |

### Thêm endpoint

```ts
userPlayerRename: playerEndpoint(
    `${prefix}/me/name`,
    {
        method: "PUT",
        body: UserRenamePlayerSchema,
        sdk: {
            summary: "Đổi tên nhân vật đang chọn.",
            auth: "player", // "none" | "user" | "player" — token nào được gắn
            response: UserPlayerMeResponse, // Zod schema, hoặc null (không có data), hoặc "raw"
            errors: [PlayerErrorCode.PLAYER_NAME_INVALID, PlayerErrorCode.PLAYER_NAME_EXISTS],
        },
    },
    handler
);
```

- Endpoint thiếu `sdk` thì export **thất bại** và liệt kê endpoint thiếu; không muốn export thì `hidden: true`.
- Schema export trong `validators/*.validator.ts|*.response.ts` được đặt tên class C# theo tên export
  (`UserCreatePlayerSchema` → `UserCreatePlayerRequest`, `UserAuthResultResponse` giữ nguyên) và dùng chung giữa
  các endpoint. Object viết inline được đặt tên theo class cha + tên field.
- `errors` chỉ ghi mã nghiệp vụ của endpoint; `INVALID_INPUT`, `MISSING_TOKEN`, `INVALID_TOKEN`,
  `INTERNAL_ERROR`, `NETWORK_ERROR` được thêm tự động vào XML doc theo `auth` và input.
- `response: "raw"` chỉ là tạm (client nhận `object`, export in cảnh báo).
- Response schema chỉ gồm field client dùng; server trả thêm field khác thì client bỏ qua. Đổi shape trả về của
  service thì sửa schema tương ứng.

### Thêm / sửa message room

Mỗi thư mục room có đúng một cặp enum (cùng file `<room>/types/<room>-message.type.ts`): `<Room>ClientMessage` (request client → server) và
`<Room>Message` (push server → client): `WorldClientMessage`/`WorldMessage`, `GlobalClientMessage`/`GlobalMessage`. Tên class C# lấy từ tên thư mục room.

1. Thêm member vào `<Room>ClientMessage` kèm JSDoc, JSDoc thành `<summary>` của hàm C#. Chỉ thêm vào `<Room>Message` khi server cần **đẩy**
   sự kiện không gắn với request nào.
2. Viết command với `static readonly message = Enum.X`, Zod schema của payload, và gán `this.result = Response.success(data)` / `Response.error(Code)`. Hàm request
   và class payload được **tự suy**.
3. Khai kiểu response và doc bằng decorator:

    ```ts
    @SdkMessage({
        response: "AttributesMessage", // DTO của data; "string" cho chuỗi; bỏ trống = không có data (C# Task<Result>)
        replies: [GlobalMessage.INVENTORY, GlobalMessage.ATTRIBUTES], // push đẩy thêm như hiệu ứng phụ
        errors: [ItemErrorCode.ITEM_CLASS_MISMATCH, PlayerErrorCode.LEVEL_TOO_LOW], // mã lỗi nghiệp vụ
        note: "Thành công: túi mới đến qua push inventory.", // trường hợp đặc biệt
    })
    export class EquipItemGlobalCommand extends InventoryGlobalCommand<...> {
    ```

    Command con gộp metadata của lớp cha: lỗi chung khai báo một lần ở lớp cha (vd `InventoryGlobalCommand`). `response` của lớp con ghi
    đè lớp cha. Command không có `@SdkMessage` vẫn có hàm request và payload, nhưng response là `Task<Result>` (không data) và thiếu doc lỗi.

4. DTO mới của `data` (response hoặc push) là interface `...Message` (phải có tên kết thúc bằng `Message` để schema-codegen sinh C#). Đặt đúng
   module: room global ở `global/modules/<feat>/interfaces/<feat>.global.message.ts` (script tự tìm file `*.message.ts` trong thư mục `interfaces/`; enum đi kèm để ở `enums/`;
   DTO mà world cũng dùng thì đặt ở `src/modules/<module>/interfaces/` và file này re-export), room world ở `world/modules/<feat>/interfaces/<feat>.world.message.ts`. Hai enum message vẫn ở `<room>/types/<room>-message.type.ts`.
   Xong chạy `yarn unity:network`.
5. Room mới: `@SdkRoom({ joins: [{ room, options: <Zod|null>, doc }] })` trên class room. Join option của `world`, `dungeon` và `global`
   đều **bắt buộc `serverId`** (khớp server của nhân vật; sai hoặc thiếu thì join bị từ chối). `world`: `{ serverId, mapCode }`;
   `dungeon`: `{ serverId, mapCode, instanceId }`; `global`: `{ serverId }`. `dungeon` là lần đăng ký thứ hai của `WorldRoom` nên dùng chung
   `WorldRoomClient` (`JoinDungeon`).

Giới hạn của tự suy: `data` của push phải có kiểu được đặt tên (`satisfies Xxx` / biến có kiểu), object literal trần sẽ ra
`Result` không có data. `response` không tự suy được, phải khai trong `@SdkMessage`. Payload chỉ suy được khi command dùng trực tiếp một
Zod schema đặt tên.

### Hình dạng C# sinh ra

Mỗi request là một hàm `async`, không ném exception:

```csharp
// WorldRoomClient (response có data)
public Task<Result<ERPG.Schema.AttributesMessage>> UpdateAttributes(UpdateAttributesRequest payload) =>
    Call<ERPG.Schema.AttributesMessage>(ERPG.Schema.WorldClientMessage.UPDATE_ATTRIBUTES, payload);
// overload phẳng: UpdateAttributes(int? strength = null, int? dexterity = null, ...)

// GlobalRoomClient (response không có data)
public Task<Result> SendWorld(ChatSendRequest payload) =>
    Call(ERPG.Schema.GlobalClientMessage.SEND_WORLD, payload);

// Push (chỉ cho member của GlobalMessage / WorldMessage)
public Action OnChatReceived(Action<ERPG.Schema.ChatReceivedMessage> onOk, Action<Result> onFail = null) => ...
```

`Call` (trong `RoomClient<T>`, `scripts/sdk/runtime`) gọi `room.Request<Result<T>>` với `RequestTimeoutMs` (mặc định 15 giây), bắn
`RoomClient.Failed` đúng một lần khi thất bại và quy lỗi ngoài nghiệp vụ về mã phía client:

| Tình huống                                       | `Result.code`                                                           |
| ------------------------------------------------ | ----------------------------------------------------------------------- |
| Chưa kết nối room / lỗi khác                     | `ClientErrorCode.NETWORK_ERROR`                                         |
| `TimeoutException` (quá `RequestTimeoutMs`)      | `ClientErrorCode.REQUEST_TIMEOUT`                                       |
| `RequestError` (vd `no_handler`, server từ chối) | `ClientErrorCode.REQUEST_FAILED` (`error` = payload của `RequestError`) |

### Mã lỗi

Thêm mã vào enum domain kèm JSDoc: khi nào server trả, client nên làm gì, `error` kèm dữ liệu gì. Chú thích đó
thành XML doc của từng hàm dùng mã đó và của hằng số trong class `*ErrorCode`. SDK không có bảng văn bản hiển thị: client map mã → locale key của game (bảng locale do game tự giữ).

## Dùng ở client

Gọi **thẳng** code sinh ra từ scene / HUD / view — không viết lớp wrap lại hàm mạng. Logic xử lý cụ thể (toast, mở modal, cập nhật state) nằm ở nơi dùng.

```csharp
// Khởi động (một lần): NetworkSession.Initialize(serverUrl) — nối ServerUrl, token (lưu PlayerPrefs), tự xoá phiên khi token hỏng.

// API: không ném exception, luôn là Result<T>. Có overload tham số phẳng cho body/payload đơn giản.
var created = await UserPlayerApi.Create(name: "An", classCode: "swordsman");
if (!created.success)
{
    if (created.Is(PlayerErrorCode.PLAYER_NAME_EXISTS)) { /* chọn tên khác */ }
    return;
}
NetworkSession.SetPlayer(created.data.playerToken);

// Room: hai client (world + global), tạo một lần. Push đăng ký trước hay sau khi join đều được (tự gắn lại khi join lại).
var world = new WorldRoomClient();
var global = new GlobalRoomClient();
global.OnInventory(inventory => Render(inventory));                                // push: chỉ gọi khi thành công
global.OnChatReceived(chat => AddLine(chat), failure => ShowError(failure.code)); // + nhánh lỗi riêng
await world.JoinWorld(new WorldJoinOptions { serverId = serverId, mapCode = "greenfield_village" }); // serverId bắt buộc
await global.JoinGlobal(new GlobalJoinOptions { serverId = serverId });
await world.WaitForFirstState();

// Request/Response: await ra Result<T>, không ném exception.
var preview = await world.PreviewAttributes(strength: 1);
if (!preview.success) { /* preview.code; RoomClient.Failed đã bắn */ }
var sent = await global.SendWorld("xin chào");
if (sent.Is(ChatErrorCode.CHAT_TOO_LONG)) { /* ... */ }
```

- **Lỗi tập trung:** `ApiClient.Failed` (API) và `RoomClient.Failed` (mọi request / push của room thất bại) bắn trước khi handler riêng chạy — bootstrap của game
  đăng ký một lần để log + toast theo locale. `ApiClient.Unauthorized` đưa về màn đăng nhập. Close code khi bị đá khỏi room: `KickCode`.
- **Request:** `await room.X(...)` trả `Result<T>` (hoặc `Result` khi response không có data); thành công đọc `data`, thất bại đọc `code`/`error`.
- **`OnX(onOk, onFail = null)` (push):** chỉ có cho message server chủ động đẩy xuống. `onOk` nhận `data` khi thành công; `onFail` nhận `Result` (có `code`, `error`)
  khi cần xử lý lỗi riêng. Push không có dữ liệu nhận `Action<Result>` cho cả hai nhánh.
- **Overload phẳng:** sinh thêm khi payload / body chỉ gồm field đơn giản; field bắt buộc đứng trước, tuỳ chọn có mặc định `null`. Tên message trùng
  thành viên của `RoomClient` (`Leave`...) được thêm tiền tố `Send` (`SendLeave`).

Chi tiết từng lớp trong `Runtime/` và cách dùng: `Network/README.md` bên Unity.
